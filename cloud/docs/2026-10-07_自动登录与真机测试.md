# v4.1.0 自动登录与真机测试

本次以独立测试服务器、公开 Markdown 和测试图片验证，不编辑私人项目、不发布私人资料。设备为已授权的 RMX3850，Android 15（SDK 35），WebView 134。

## 使用方式

电脑：设置 → 云同步。手机：登录。默认勾选“记住登录，下次自动登录”，首次输入账号密码后，后续重开可自动恢复，普通会话过期会自动续期。

- 取消勾选：只登录本次，下一次启动需要手动登录。
- 退出账号：清除本机记住的登录，并在网络可用时撤销服务端令牌；本地大纲保留。
- 自动登录和自动云同步彼此独立，记住账号不代表必须开启后台同步。
- 长期不使用超过 180 天，或凭据被撤销、损坏后，需重新输入账号密码。
- 密码只参与首次登录；电脑凭据由 Windows DPAPI 保护，手机凭据用 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) 的 AES-GCM 密钥加密。浏览器版使用浏览器本地存储，不冒充操作系统凭据保险箱。

## 测试中修复的问题

1. Windows 版旧 aapt2 把 APK 的 `assets/web/index.html` 等路径写成反斜杠，Android 无法按规范路径找到页面。构建现在统一 ZIP 项目路径为正斜杠，检测重复与必要资源，校验 CRC，之后再对齐、签名。正式包与测试包都使用该步骤。
2. 对话框打开后的延迟自动聚焦会抢走已选择的密码输入框焦点。现在只在焦点仍停留在对话框默认位置时执行首次聚焦。
3. WebView 不支持桌面浏览器的下载目录初始化命令。测试工具只在本机测试连接中跳过这条框架命令，其余操作均转发给真实 WebView，不修改安装环境的 Playwright。

正式 APK 保持 HTTPS、禁止明文流量、关闭 WebView 调试。只有单独的测试 APK 能使用本机 HTTP 和调试接口。测试临时 ADB 端口转发会清理。

## 正式安装与上线验证

正式服务器已升级到 v4.1.0，升级前在专属项目目录内备份源码和 SQLite，不改 Nginx 或其他项目。现有 24 份云端大纲未被测试编辑。

手机上已完成正式 HTTPS 账号登录、重启后的自动恢复，接收到 24 个现有云项目，并覆盖安装同签名的正式 APK；正式安装不带 DEBUGGABLE 标志，没有该应用的 WebView 调试端口。电脑原位置单文件程序已原位升级到 v4.1.0，正常保存退出后恢复启动，原快捷方式保持不变。说明里的登录用法已更新。

本机原有 Markdown 与 Media 共 43 个文件在原位升级前后哈希一致。手机厂商禁止 ADB 直接清空应用资料，因此仅在核对应用私有路径和本轮测试来源后，把新装测试版生成的 WebView 缓存及测试登录配置移到同一应用私有目录的可恢复测试备份，不改手机的权限或系统设置。正式资料使用新缓存，与测试资料隔离。

正式结果：`.cache/adb-qa/live-result.json`。服务端下载 APK 的 SHA-256 与本机正式包一致；本地 `dist/发布校验.json` 记录最终校验值。

## 复测

在无私人资料的专用测试安装上运行。若手机已有自己在用的安装，脚本默认停止；`--retry-own-install` 仅用于本轮已由测试脚本安装的程序，不用于跳过对私人资料的检查。

```powershell
pwsh -NoLogo -NoProfile -File scripts/build_android.ps1 -Debuggable
python scripts/verify_adb.py --serial c9f78ecf --desktop-executable ../项目航图/dist/项目航图.exe
python -m pytest tests -q --basetemp .cache/auto-login-tests
node --test tests/*.test.mjs
```
