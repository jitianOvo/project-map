# 部署与维护

## 本次范围

服务端项目位于 `/root/项目航图`，与现有其他项目并列。除经过授权的下面两项外，没有改动其他项目文件：

1. 在 Nginx 的现有 HTTPS 虚拟主机中增加 `include "/root/项目航图/deploy/nginx-location.conf";`。新入口为 `/project-map/`，转发至 `127.0.0.1:18770`。
2. 增加 `/etc/systemd/system/project-map-cloud.service`，只启动项目航图服务。Nginx 使用平滑 reload，不停止现有服务。

原 Nginx 配置备份位于本项目 `.deploy/<部署时间>/nginx-default.before`，部署记录在 `.deploy/deployment.json`。服务只绑定本机地址，不额外开放公网 HTTP 端口；手机和电脑均使用已有的 HTTPS 入口。

## 运行

```bash
systemctl status project-map-cloud.service
systemctl restart project-map-cloud.service
curl http://127.0.0.1:18770/api/health
curl https://jitian666.me/project-map/api/health
```

服务由 systemd 自动启动并在异常退出后重启。源码、运行数据、图片、首次账户配置均在本项目内。systemd 限制服务的可写路径为该项目；它不会写入其他项目目录。

后端使用 Python 3.12 标准库，无数据库服务器、Docker、Node 常驻进程或第三方 Python 服务端依赖。

## 账户

应用初始账户为 `owner`。独立随机密码只保存在本项目 `.secrets/首次登录.txt`，经 SSH 复制了一份到 Windows 云端项目 `.secrets/云端首次登录.txt`。没有把 SSH 密码写进源码、APK、日志或网页资源。

数据库保存会话令牌的哈希，令牌有效期为 30 天。账户密码使用带随机盐的 scrypt 哈希。登录会限制失败尝试次数。退出登录撤销当前令牌，但本机缓存仍保留。

这是一个个人工作区；所有登录同一账户的设备都访问同一套项目，不是多用户权限隔离系统。请勿把应用账户发给无关人员。

## 备份

服务第一次有同步写入时生成当天的 SQLite 一致性快照，每天最多一次，位于 `runtime/backups/`。这是数据库备份，不含图片。客户端还可以导出包含已缓存图片的 JSON 备份。

服务端完整迁移至少保留：

- `runtime/projects.sqlite3` 的一致性备份；
- `runtime/media/`；
- `.secrets/account.json`；
- 程序源码及 `server/public/`。

不要在服务运行时只复制 SQLite 主文件而忽略 WAL。简便做法是停掉该专属服务后复制整个项目，再启动它；不会影响其他服务。当前没有配置异地备份和自动磁盘清理，需要定期把备份复制到另一设备，并检查本项目磁盘占用。服务端历史保留用于冲突基线和恢复；客户端展示最近 50 次。

## 更新

构建共享资源和 APK 后，将 `server/` 和本项目部署文件上传到本目录。保留 `.secrets`、`runtime`、`.deploy`，不要覆盖账户或数据库。只重启 `project-map-cloud.service`。只有路由配置变动时才需要检查并 reload Nginx。

公开下载目录只放安装包，不放任何私人 Markdown、数据库、账户配置或备份。客户端 Markdown 导入需要手动操作，不会自动扫描旧 Windows 项目。

## 本机网络

Windows 原生网络桥直连配置的 HTTPS 服务器，验证系统认可的证书，不跟随跨站重定向，不修改系统代理设置。网页版遵循浏览器网络配置。Android 原生网络桥同样验证 HTTPS 证书；没有关闭证书验证或使用明文公网连接。
